# ALL AT A1 Job Portal Knowledge Transfer (KT)
Date: 2026-02-22

## Project Overview
The ALL AT A1 Job Portal is a frontend web application with a Flask backend designed to aggregate job listings. The theme matches the client's custom logo incorporating 4 distinct colors.

## File Structure & Contents
- `index.html`: The main structural file for the job portal. Contains the header, search hero, sidebar filters, job listing placeholders, and footer. It has been customized with the "ALL AT A1" branding and an updated "Legal Agreements" navigation link.
- `styles.css`: The styling file containing all visual designs. It uses CSS variables at the root level corresponding to the extracted 4-color palette from the logo (Blue, Teal, Red/Rust, Yellow/Orange). 
- `script.js`: Client-side JavaScript containing dummy job data, layout rendering logic, and mock interactivity (e.g., save job, apply button functionalities).
- `app.py`: A Python Flask local server. It serves the portal files and automatically opens the browser at `http://127.0.0.1:5000/`. It also includes a placeholder endpoint at `/api/jobs` intended for future web scraping uploads using API key authentication.
- `get_color.py`: A Python development utility script that uses Pillow to isolate and extract the top distinct high-contrast colors from the `Logo.png` file, successfully establishing the 4-color theme mapping.
- `requirements.txt`: Tracks backend python requirements including `Flask` and `Pillow`.
- `Logo.png`: The client's brand logo file used in the header and footer branding.
- `KT.txt`: This documentation file.

## Recent Implementations (Contact & Admin Features)
- **Contact Form & DB:** Integrated a live `ContactMessage` model (Name, Email, Subject, Body) connected to a remote Xata PostgreSQL Database via `.env`-stored `DATABASE_URL`.
- **Custom Success Modal:** Replaced the ugly browser `alert()` pop-up on successful contact form submission with a sleek, centered "Success!" modal overlay (`contact.html`). 
- **Secret Admin Panel:** Created a hidden Admin Panel at `admin.html`. Access it securely using a long, obscure URL secret string.
- **Environment Security:** Migrated the long admin secret route to the local `.env` file under `ADMIN_PATH` to prevent repo leaks.
- **Log Masking:** Wrote a custom Werkzeug `logging.Filter` interceptor in `app.py` to automatically detect the `ADMIN_PATH` in console logs and replace it with `0-------------------------------------------------------------0` to prevent shoulder-surfing.
- **Message Table Retrieval:** Modified the `admin.html` dashboard natively default to the Messages tab, dynamically fetching the live Xata data from the `GET /api/admin/messages` endpoint.
- **Message Details Overlay:** Made each message table row clickable to open a large UI modal containing the full, extended email text without squishing the table layout.
- **Delete Record Capability:** Implemented a new `DELETE /api/admin/messages/<id>` backend route (using modernized SQLAlchemy 2.0+ `db.session.get` syntax to clear legacy warnings). Supported it with a three-dots `...` action menu on table rows opening a "Delete" dropdown.
- **Safe Deletion UI:** Embedded a centered Warning Confirmation Modal ("Are you sure...") before deletion to prevent accidental destructs, actively refreshing the table state upon success.

## Latest Updates (as of 2026-02-24)
- **Database Seeding:** Created a `Job` SQLAlchemy model and seeded the Xata database with 10 dummy jobs to migrate away from hardcoded frontend data.
- **API Key Protection:** Added an `X-API-KEY` header requirement to `/api/jobs` controlled by the `.env` `API_KEY` variable to stop simple unauthorized scraping.
- **Anti-Scraping Server-Side Rendering (SSR):** Completely removed the `jobs` Javascript scraping loophole. The Flask backend (`app.py`) now reads `index.html`, queries the protected Xata database, filters jobs securely based on URL parameters, and injects the raw HTML directly before sending to the browser.
- **Clean URL state:** Modified the job filtering system to use clean URL parameters (`?jobtype=Full-time&workmodel=On-site`).
- **Checkbox Restoration:** Built Javascript logic to automatically read the URL parameters on page load and visually re-check the correct sidebar filters.
- **Remove Filters:** Added a "Remove Filters" button to the sidebar that clears all URL query strings, actively unchecking all boxes and reloading the full job list.
- **Upload Key Separation:** Added a dedicated `X-UPLOAD-KEY` requirement for `POST` requests to `/api/jobs` so scraping uploads are completely isolated from standard `GET` requests.
- **Crash-proof POST insertion:** Designed the `app.py` `/api/jobs` POST logic to safely use `.get()` with `or` operator fallbacks to gracefully insert placeholder text into the Xata database if a scraping script misses a required field or provides an empty string.
- **Data Initialization Cleanup:** Removed the legacy 10-job dummy data creation script from `app.py` and purged the Xata database, ensuring only original uploaded jobs are rendered.
- **SSR Pagination Layer:** Replaced static HTML pagination with dynamic Server-Side calculated pagination. Hard-capped the view at 8 jobs per page (`per_page = 8`). Created dynamic `<a class="btn-page">` tags that inject `/?page=2` style URL modifications securely while appending existing `&workmodel` query states.
